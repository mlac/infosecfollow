1. SCREENCONNECT AND N-CENTRAL ATTACKS REACH CUSTOMER ENDPOINTS
   Vulnerabilities and Exploits · [zero-day, msp, exploit]
   Latest developments: Attackers began exploiting
   4EverAble2Shell, the N-central zero-day a researcher
   published this week, within hours of the proof of concept,
   planting cryptocurrency miners on at least 21 servers, 19 of
   them running N-able's newest security update, and N-able says
   the server flaw depends on a non-default configuration in
   which an administrator turns the Legacy API on and exposes it
   to the public internet; Blackpoint Cyber's Adversary Pursuit
   Group identified the ScreenConnect attacker toolkit as SCKit,
   which exploits the already-patched CVE-2026-84869 rated 9.9
   and spreads worm-like from infected customer devices to the
   computers of managed service provider technicians and onward
   into other managed networks; and ConnectWise disabled five
   third-party ScreenConnect extensions in partner environments
   after attackers abused a flaw in one legitimate extension to
   walk past ScreenConnect authentication and push rogue
   remote-access clients onto at least 288 endpoints across 48
   organizations, with no compromise of its own infrastructure.
   Both products are remote monitoring and management platforms
   that managed service providers use to administer client
   machines, which gives one compromised instance reach into
   every customer it serves. Administrators should apply
   N-able's hotfixes, take the Legacy API off the internet,
   patch ScreenConnect against CVE-2026-84869, check which
   extensions their environment loads, and hunt for unexpected
   remote-access clients on managed endpoints.

6. STOLEN CLAUDE KEYS TURN CLAUDE CODE INTO AN IMPLANT
   AI Security · [ai, credentials, c2]
   Latest developments: Darktrace researchers showed in a lab
   test that an attacker holding a stolen Claude API key can run
   Claude Code as a remote-controlled implant, steering the
   coding agent through the memory stores feature of Anthropic's
   platform and pulling a one-gigabyte file out through the
   Claude Files API, with every task and every result traveling
   to api.anthropic.com, the same endpoint the agent already
   calls for inference; Microsoft Defender Research and the AI
   Red Team published a companion attack path on November 12,
   2026, showing how poisoned training datasets and poisoned
   model checkpoints hijack a coding agent into remote code
   execution after training ends; Anthropic opened a private
   beta of a self-hosted Claude Managed Agents that keeps the
   agent harness, sandboxes, credentials, and session history
   inside a customer's own cloud or data center; and Unit 42,
   the Palo Alto Networks research group, published mitigations
   for attacker use of AI red team tools including ARTEX.
   A coding agent already installed and trusted on a developer
   workstation becomes the command channel, and its traffic
   blends into ordinary agent activity that network monitoring
   treats as benign. Treat Claude API keys as production
   credentials, rotate exposed ones, pin the provenance of any
   model weights or post-training datasets you load, and watch
   for agent sessions that no developer started.

10. GSOCKET KEEPS LINUX SERVERS OWNED AFTER PATCHING
   Ransomware and Cybercrime · [linux, malware, persistence]
   Latest developments: Microsoft Threat Intelligence documented
   multiple threat actors planting GSocket, a legitimate
   open-source remote access tool, on compromised Linux servers
   to hold encrypted command and control after the victim
   patches the vulnerability that let the attacker in, and
   published detection, investigation, and remediation steps;
   the threat intelligence company Flare reported separately
   that underground forums now trade eBPF rootkit source code,
   tutorials, and exploits that hide activity on Linux without
   loading a kernel module.
   Patching an exploited flaw closes the door the attacker used
   and leaves the attacker inside, because GSocket rides
   outbound encrypted connections that look like administrative
   traffic. After any Linux server compromise, hunt for GSocket
   processes, unexpected cron and systemd persistence, and eBPF
   programs loaded outside your own tooling.
