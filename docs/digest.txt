1. PHP2SHELL DRAWS MASS MIRAI SCANNING
   Vulnerabilities and Exploits · [zero-day, patch, botnet]
   Latest developments: PHP disclosed a third remote code
   execution flaw, CVE-2026-115560, on October 23, 2026, two
   days after its emergency patches, and shipped no fix for it,
   telling administrators to turn off the feature involved
   because the bug reaches only web applications running an
   unusual configuration; the SANS Internet Storm Center
   returned its InfoCon gauge to green Friday morning and now
   doubts the original pair exploits reliably at all, Unit 42
   updated its threat brief the same day, and researchers still
   confirm no successful compromise out of millions of attempts
   to enlist servers in the Mirai variant Potassium, even as
   exploit code that bypasses address space layout randomization
   circulates.
   The pair of PHP flaws, each rated 9.2, give an
   unauthenticated attacker remote code execution on any PHP
   installation serving web requests, with the highest risk on
   Apache with mod_php and on PHP-FPM. Every site on PHP 8.2
   through 8.5 needs the October 21, 2026 releases 8.5.12,
   8.4.27, 8.3.36, and 8.2.35.

3. PILLOW AND NODE.JS DECODERS RUN ATTACKER CODE
   Vulnerabilities and Exploits · [patch, rce, supply-chain]
   Latest developments: Ruby shipped versions 4.0.9, 3.4.12, and
   3.3.13 on October 23, 2026 to fix three bugs in Onigmo, its
   built-in regular expression engine, which sit behind the four
   critical GitLab remote code execution flaws of the past
   month, because a crafted pattern corrupts memory while Ruby
   compiles it; researchers disclosed CVE-2026-112900 in Pillow,
   the most widely used image library for Python, which passes
   an EPS file's name straight to Ghostscript and so runs
   whatever operating system command a caller buries in that
   name; Imperva published Node2Shell, a proof of concept that
   executed code on the official Node.js 24.22.0 image for Linux
   arm64 by feeding crafted data to the bundled Brotli decoder,
   CVE-2026-111497; and Atlassian's October bulletin listed 176
   vulnerability entries, 14 of them critical, all in
   third-party components of its Data Center and Server
   products.
   Pillow decodes uploaded images across Python web
   applications, so any server that opens an attacker-named EPS
   file hands over a shell, and the Node.js proof of concept
   needed no debugger or custom build. Teams running Ruby,
   Pillow, Node.js, or Atlassian Data Center should install the
   current releases.
   - The Hacker News: https://thehackernews.com/2026/10/critical-flaw-in-pythons-popular-pillow.html

5. APT41 BOOTKIT AND SANDWORM'S MESH BACKDOOR
   Nation-State Activity · [apt, espionage, wiper]
   Latest developments: Kaspersky said the BlackX UEFI bootkit
   defeats Secure Boot on fully patched Windows machines whose
   owners never applied the certificate revocations for
   CVE-2022-21894, and named the victims as diplomatic
   organizations in Tajikistan, Uzbekistan, and Turkmenistan hit
   in early 2026, with suspicion falling on the China-linked
   group APT41; ESET detailed the Ukrainian case, reporting that
   UAC-0099, also called Earth Sirrush, phished its way into a
   logistics company on July 16, 2025 and passed access to
   Sandworm, which installed a previously unseen mesh network
   backdoor before destroying data; and SecurityWeek reported
   that Iran's Prince of Persia group broke a three-month lull
   by hiding a Tornado command-and-control server on United
   States shared hosting, its first server in the country since
   2016.
   A bootkit that runs before Windows loads survives
   reinstallation and hides from every tool inside the operating
   system, and the Secure Boot fix requires loading the
   revocation list, a step many fleets skipped. Administrators
   should apply the CVE-2022-21894 revocations, and defenders
   tracking Iranian activity should stop treating domestic
   hosting as a trust signal.
   - The Hacker News: https://thehackernews.com/2026/10/blackx-uefi-bootkit-bypasses-secure.html

9. MICROSOFT 365 SESSION REPLAY HITS 79 ORGANIZATIONS
   Data Breaches · [credential-theft, cloud, breach]
   Latest developments: Huntress reported on October 23, 2026
   that one attacker spent ten weeks replaying stolen Microsoft
   365 sign-in sessions against 79 organizations between July 14
   and September 22, 2026, logging 497 successful sign-ins and
   more than 200,000 failed login attempts, planting hidden
   inbox rules that kept victims from seeing parts of their own
   mail, and running the replays from servers at the hosting
   provider 1337 Services GmbH.
   A replayed session needs no password and no multi-factor
   code, so credential defenses miss it entirely. Security teams
   should revoke active sessions whenever they suspect a
   compromise, audit mailbox rules for hidden filters, and watch
   sign-ins from 1337 Services GmbH address space.
   - Help Net Security: https://www.helpnetsecurity.com/2026/10/23/microsoft-365-accounts-stolen-sessions/
