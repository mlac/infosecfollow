2. Pillow and Node.js Decoders Run Attacker Code

Vulnerabilities and Exploits · [patch, rce, supply-chain]

Latest developments: Researchers disclosed CVE-2026-112900 in Pillow, the most widely used image library for Python, which passes an EPS file's name straight to Ghostscript and so runs whatever operating system command a caller buries in that name; Imperva published Node2Shell, a proof of concept that executed code on the official Node.js 24.22.0 image for Linux arm64 by feeding crafted data to the bundled Brotli decoder, CVE-2026-111497; and Atlassian's October bulletin listed 176 vulnerability entries, 14 of them critical, all in third-party components of its Data Center and Server products.

read more

Pillow decodes uploaded images across Python web applications, so any server that opens an attacker-named EPS file hands over a shell, and the Node.js proof of concept needed no debugger or custom build. Teams running Pillow, Node.js, or Atlassian Data Center should install the current releases.

Vulnerabilities and Exploits · [zero-day, patch, botnet]

Latest developments: Attackers now fire millions of exploit attempts at CVE-2026-109618 and CVE-2026-109619 to enlist servers in Potassium, a variant of the Mirai botnet, and the attempts fail so far as researchers find the two bugs harder to weaponize than they first thought.

The pair of PHP flaws, each rated 9.2, give an unauthenticated attacker remote code execution on any PHP installation serving web requests, with the highest risk on Apache with mod_php and on PHP-FPM. Every site on PHP 8.2 through 8.5 needs the October 21, 2026 releases 8.5.12, 8.4.27, 8.3.36, and 8.2.35.

5. Attackers Hijack Exposed AI Models and Agent Wallets

AI Security · [ai, agent, vulnerability]

Latest developments: Symantec researchers Priti More and Susmit Yenkar captured the instruction set of an attack tool that scans for AI models anyone on the internet can reach and then uses them to plan break-ins while the model's owner pays for the computing power, after its operators sent their entire working prompt to a honeypot posing as an unprotected AI service; the security firm V12 reported on October 22, 2026 that the default client in the x402 SDKs set no spending limit until the August 18 releases added one, so a malicious API could get an agent to sign a payment for its full balance of a supported token.

read more

Both problems punish AI infrastructure left open by default: an unauthenticated model endpoint becomes an attacker's free hacking engine, and an agent that signs payments automatically becomes a wallet to empty. Operators should authenticate every model endpoint and set per-call spending caps on agent payment SDKs.
