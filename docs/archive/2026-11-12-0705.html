1. ScreenConnect and N-central Attacks Reach Customer Endpoints

Vulnerabilities and Exploits · [zero-day, msp, exploit]

Latest developments: ConnectWise disabled five third-party ScreenConnect extensions in partner environments after attackers exploited a flaw in one legitimate extension to walk past ScreenConnect authentication and push rogue remote-access clients onto at least 288 endpoints across 48 organizations, and the company says it sees no compromise of its own infrastructure and no vulnerability in ScreenConnect itself; SecurityWeek reported that attacks on N-able N-central began shortly after a researcher published more than 30 zero-days, and that N-able's hotfixes close the ones an unauthenticated attacker can reach.

read more

Both products are remote monitoring and management platforms that managed service providers use to administer client machines, which gives one compromised instance reach into every customer it serves. Administrators should apply N-able's hotfixes, check which ScreenConnect extensions their environment loads, and hunt for unexpected remote-access clients on managed endpoints.

2. HTTP/2 and Pre-Auth Flaws Hit Core Server Software

Vulnerabilities and Exploits · [patch, rce, open-source]

Latest developments: The Apache Software Foundation fixed CVE-2026-119618, a critical remote code execution flaw in the mod_http2 module that affects Apache HTTP Server 2.4.55 through 2.4.70, in version 2.4.71 on November 11, 2026, and Red Hat, which ships the server with Red Hat Enterprise Linux, says only hosts with HTTP/2 enabled face exposure; Node.js closed 16 flaws in versions 22.23.5, 24.22.3, and 26.13.1, two of them in built-in HTTP/2 support that let an unauthenticated client crash a 24.x or 26.x server or pull back pieces of server memory holding other connections' responses; MongoDB patched CVE-2026-118383, which lets an unauthenticated attacker send two requests that crash a lagging replica set member once it takes over as primary; and Red Hat patched a critical Quay flaw that lets attackers steal private container images, overwrite repositories, and hold persistent access.

read more

These are the web servers, runtimes, databases, and registries sitting under most enterprise applications, and three of the four flaws need no credentials at all. Inventory internet-facing Apache and Node.js hosts with HTTP/2 turned on, patch to 2.4.71 and the fixed Node.js lines, and update MongoDB replica set members and Quay registries.

3. GSocket Keeps Linux Servers Owned After Patching

Ransomware and Cybercrime · [linux, malware, persistence]

Latest developments: Microsoft Threat Intelligence documented multiple threat actors planting GSocket, a legitimate open-source remote access tool, on compromised Linux servers to hold encrypted command and control after the victim patches the vulnerability that let the attacker in, and published detection, investigation, and remediation steps; the threat intelligence company Flare reported separately that underground forums now trade eBPF rootkit source code, tutorials, and exploits that hide activity on Linux without loading a kernel module.

read more

Patching an exploited flaw closes the door the attacker used and leaves the attacker inside, because GSocket rides outbound encrypted connections that look like administrative traffic. After any Linux server compromise, hunt for GSocket processes, unexpected cron and systemd persistence, and eBPF programs loaded outside your own tooling.

5. Stolen GitHub Accounts Seed a Secret Stealer

Software Supply Chain Security · [supply-chain, breach, credentials]

Latest developments: Aikido Security disclosed a campaign it calls wfx-loot, in which an attacker holding stolen credentials for 4,837 GitHub accounts pushed a credential-stealing payload into tens of thousands of repositories starting Tuesday, November 10, 2026, and ran it in at least 1,806 of them, shipping GitHub Actions secrets and cloud credentials back out; the compromised accounts also opened probe pull requests across the repositories they could write to.

read more

GitHub Actions workflows carry the secrets that reach cloud accounts, container registries, and production systems, so every secret the malware touched counts as burned. Anyone whose repositories accepted commits or workflow runs since November 10, 2026 should rotate Actions secrets and cloud credentials, revoke tokens, and audit recent pull requests and commit authors.

Sources: Help Net Security · The Hacker News · ↑ top

6. Stolen Claude Keys Turn Claude Code Into an Implant

AI Security · [ai, credentials, c2]

Latest developments: Darktrace researchers showed in a lab test that an attacker holding a stolen Claude API key can run Claude Code as a remote-controlled implant, steering the coding agent through the memory stores feature of Anthropic's platform and pulling a one-gigabyte file out through the Claude Files API, with every task and every result traveling to api.anthropic.com, the same endpoint the agent already calls for inference; Unit 42, the Palo Alto Networks research group, published mitigations the same day for attacker use of AI red team tools including ARTEX.

read more

A coding agent already installed and trusted on a developer workstation becomes the command channel, and its traffic blends into ordinary agent activity that network monitoring treats as benign. Treat Claude API keys as production credentials, rotate exposed ones, and watch for agent sessions that no developer started.
