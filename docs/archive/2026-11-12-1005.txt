1. SCREENCONNECT AND N-CENTRAL ATTACKS REACH CUSTOMER ENDPOINTS
   Vulnerabilities and Exploits · [zero-day, msp, exploit]
   Latest developments: N-able opened a second investigation on
   November 12, 2026 into a fresh public disclosure of more
   flaws in on-premises N-central 2026.4.1 HF2, the
   already-hotfixed release, with exploits that claim root
   remote code execution and Windows SYSTEM access, and the
   company says the server issue depends on a non-default
   configuration in which an administrator turns the Legacy API
   on and exposes it to the public internet; ConnectWise
   disabled five third-party ScreenConnect extensions in partner
   environments after attackers exploited a flaw in one
   legitimate extension to walk past ScreenConnect
   authentication and push rogue remote-access clients onto at
   least 288 endpoints across 48 organizations, and the company
   sees no compromise of its own infrastructure and no
   vulnerability in ScreenConnect itself.
   Both products are remote monitoring and management platforms
   that managed service providers use to administer client
   machines, which gives one compromised instance reach into
   every customer it serves. Administrators should apply
   N-able's hotfixes, take the Legacy API off the internet,
   check which ScreenConnect extensions their environment loads,
   and hunt for unexpected remote-access clients on managed
   endpoints.

2. HTTP/2 AND PRE-AUTH FLAWS HIT CORE SERVER SOFTWARE
   Vulnerabilities and Exploits · [patch, rce, open-source]
   Latest developments: PTC patched CVE-2026-126325, an improper
   input validation and untrusted deserialization flaw rated 9.2
   in its Windchill and FlexPLM product lifecycle management
   software that hands an attacker remote code execution; the
   Apache Software Foundation fixed CVE-2026-119618, a critical
   remote code execution flaw in the mod_http2 module that
   affects Apache HTTP Server 2.4.55 through 2.4.70, in version
   2.4.71 on November 11, 2026, and Red Hat, which ships the
   server with Red Hat Enterprise Linux, says only hosts with
   HTTP/2 enabled face exposure; Node.js closed 16 flaws in
   versions 22.23.5, 24.22.3, and 26.13.1, two of them in
   built-in HTTP/2 support that let an unauthenticated client
   crash a 24.x or 26.x server or pull back pieces of server
   memory holding other connections' responses; MongoDB patched
   CVE-2026-118383, which lets an unauthenticated attacker send
   two requests that crash a lagging replica set member once it
   takes over as primary; and Red Hat patched a critical Quay
   flaw that lets attackers steal private container images,
   overwrite repositories, and hold persistent access.
   These are the web servers, runtimes, databases, registries,
   and engineering platforms sitting under most enterprise
   applications, and three of the flaws need no credentials at
   all. Inventory internet-facing Apache and Node.js hosts with
   HTTP/2 turned on, patch to 2.4.71 and the fixed Node.js
   lines, and update Windchill, FlexPLM, MongoDB replica set
   members, and Quay registries.

4. STOLEN GITHUB ACCOUNTS SEED A SECRET STEALER
   Software Supply Chain Security · [supply-chain, breach,
   credentials]
   Latest developments: SecurityWeek put the reach of the
   wfx-loot campaign at roughly 60,000 GitHub repositories,
   extending Aikido Security's account of an attacker who holds
   stolen credentials for 4,837 GitHub accounts, pushed a
   credential-stealing payload into tens of thousands of
   repositories starting Tuesday, November 10, 2026, and ran it
   in at least 1,806 of them, shipping GitHub Actions secrets
   and cloud credentials back out; the compromised accounts also
   opened probe pull requests across the repositories they could
   write to.
   GitHub Actions workflows carry the secrets that reach cloud
   accounts, container registries, and production systems, so
   every secret the malware touched counts as burned. Anyone
   whose repositories accepted commits or workflow runs since
   November 10, 2026 should rotate Actions secrets and cloud
   credentials, revoke tokens, and audit recent pull requests
   and commit authors.
   - Help Net Security: https://www.helpnetsecurity.com/2026/11/12/wfx-loot-github-actions-secret-stealer/
   - The Hacker News: https://thehackernews.com/2026/11/4837-hijacked-github-accounts-ran-ci.html

6. GSOCKET KEEPS LINUX SERVERS OWNED AFTER PATCHING
   Ransomware and Cybercrime · [linux, malware, persistence]
   Latest developments: Microsoft Threat Intelligence documented
   multiple threat actors planting GSocket, a legitimate
   open-source remote access tool, on compromised Linux servers
   to hold encrypted command and control after the victim
   patches the vulnerability that let the attacker in, and
   published detection, investigation, and remediation steps;
   the threat intelligence company Flare reported separately
   that underground forums now trade eBPF rootkit source code,
   tutorials, and exploits that hide activity on Linux without
   loading a kernel module.
   Patching an exploited flaw closes the door the attacker used
   and leaves the attacker inside, because GSocket rides
   outbound encrypted connections that look like administrative
   traffic. After any Linux server compromise, hunt for GSocket
   processes, unexpected cron and systemd persistence, and eBPF
   programs loaded outside your own tooling.
   - Microsoft Security Blog: https://www.microsoft.com/en-us/security/blog/2026/11/11/global-socket-how-threat-actors-weaponizing-gsocket-stealthy-c2/
   - BleepingComputer: https://www.bleepingcomputer.com/news/security/hackers-plant-gsocket-on-linux-servers-for-persistent-access/
   - BleepingComputer: https://www.bleepingcomputer.com/news/security/ebpf-rootkits-why-underground-actors-are-taking-notice/

9. STOLEN CLAUDE KEYS TURN CLAUDE CODE INTO AN IMPLANT
   AI Security · [ai, credentials, c2]
   Latest developments: Darktrace researchers showed in a lab
   test that an attacker holding a stolen Claude API key can run
   Claude Code as a remote-controlled implant, steering the
   coding agent through the memory stores feature of Anthropic's
   platform and pulling a one-gigabyte file out through the
   Claude Files API, with every task and every result traveling
   to api.anthropic.com, the same endpoint the agent already
   calls for inference; Unit 42, the Palo Alto Networks research
   group, published mitigations the same day for attacker use of
   AI red team tools including ARTEX.
   A coding agent already installed and trusted on a developer
   workstation becomes the command channel, and its traffic
   blends into ordinary agent activity that network monitoring
   treats as benign. Treat Claude API keys as production
   credentials, rotate exposed ones, and watch for agent
   sessions that no developer started.
   - Help Net Security: https://www.helpnetsecurity.com/2026/11/12/stolen-claude-api-keys-remote-controlled-implant/
   - Unit 42 (Palo Alto): https://unit42.paloaltonetworks.com/artex-and-ai-powered-red-teaming-tools/

10. OPERATION ENDGAME SEIZES GOOTLOADER AND STEALC SERVERS
   Ransomware and Cybercrime · [malware, takedown, cybercrime]
   Latest developments: Police in nine countries, coordinating
   through Europol, seized the servers behind the Gootloader,
   CastleRAT, and StealC malware operations this week and
   recovered more than 6 million credentials stolen from
   infected computers, the newest round of Operation Endgame,
   the campaign aimed at the access services ransomware crews
   buy from.
   Gootloader, CastleRAT, and StealC harvest logins from
   ordinary users and company machines, and their operators sell
   that access onward to ransomware affiliates. Treat any
   credential a corporate endpoint typed this year as suspect,
   force password resets, and revoke live sessions and tokens.
   - Help Net Security: https://www.helpnetsecurity.com/2026/11/12/europol-operation-endgame-malware-takedown/
