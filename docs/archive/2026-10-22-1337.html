1. PHP2Shell Exploitation Began Before Disclosure

Vulnerabilities and Exploits · [zero-day, patch, exploit]

Latest developments: Amazon's threat intelligence team, whose chief information security officer CJ Moses described the finding, said its MadPot honeypot service logged an exploit attempt from a commercial anonymization network on October 17, 2026, four days before the PHP Foundation disclosed CVE-2026-109618 and CVE-2026-109619, and broad scanning followed within hours of the patches; Searchlight Cyber released php2shell-scanner, an open-source tool that tests a host for both bugs, and researchers now confirm exploitation against WordPress, Drupal, Joomla, phpMyAdmin, Nextcloud, and Magento installations; Palo Alto Networks confirmed that every version of PAN-OS and Panorama carries the flaws and has shipped no fixed release, Fortinet is checking 12 products and Cisco 31 products and cloud services, and OpenAI proposed a five-stage disclosure process for critical open-source bugs after Calif found one of the two flaws with the GPT-5.6 Sol model under OpenAI's Patch the Planet initiative and Wiz reported both independently.

read more

PHP2Shell is a pair of critical flaws in the PHP runtime that run an unauthenticated attacker's code on any server answering web requests, regardless of the application on top. CISA tells organizations to move to PHP 8.5.12, 8.4.27, 8.3.36, or 8.2.35 immediately; customers of appliances that embed PHP, among them PAN-OS and Panorama, must wait on vendor builds and restrict management interfaces meanwhile.
