3. X47.C BOTNET ASKS XAI GROK WHAT TO DO NEXT
   AI Security · [ai, botnet, malware]
   Latest developments: SecurityWeek described x47.c on
   September 26, 2026, a Windows botnet that queries xAI's Grok
   to pick from a set of predefined actions and keep itself
   alive on an infected machine, and that drains the AI API
   accounts it reaches.
   x47.c joins a run of malware that treats commercial models as
   its brain and stolen model credentials as its fuel, alongside
   the Docker botnet SecurityWeek reported hunting AI keys on
   exposed daemons. Defenders should scope which hosts hold AI
   API keys, cap spending on those accounts, and alert on
   outbound traffic to model endpoints from servers that have no
   business talking to them.
   - SecurityWeek: https://www.securityweek.com/new-x47-c-windows-botnet-weaponizes-xai-grok-ai-api-draining/
   - SecurityWeek: https://www.securityweek.com/in-other-news-clop-leak-site-takeover-docker-botnet-hunts-ai-keys-water-utility-exposure/

4. ELEMENTOR FLAW MINTS WORDPRESS ADMINISTRATORS
   Vulnerabilities and Exploits · [patch, wordpress,
   vulnerability]
   Latest developments: Researchers detailed a cross-site
   request forgery flaw in the Elementor Website Builder plugin
   for WordPress on September 26, 2026, rated 8.8 and still
   carrying no CVE identifier, that lets an attacker with no
   account create rogue administrator accounts and take over a
   site.
   Elementor runs on millions of WordPress sites, and the bug
   turns one crafted link, opened by a logged-in administrator,
   into full control of the site. Site owners should update
   Elementor immediately and audit their administrator lists for
   accounts nobody created.
   - The Hacker News: https://thehackernews.com/2026/09/elementor-csrf-flaw-lets-attackers-take.html
   - BleepingComputer: https://www.bleepingcomputer.com/news/security/elementor-wordpress-flaw-lets-attackers-create-admin-accounts/

6. MINI SHAI-HULUD MALWARE RESTARTS IN GITHUB ACTIONS
   Software Supply Chain Security · [supply-chain, malware]
   Latest developments: GitHub disabled two actions-cool GitHub
   Actions for a second time after the repositories,
   actions-cool/issues-helper and
   actions-cool/maintain-one-comment, came back online last week
   and resumed executing the Mini Shai-Hulud malware that
   compromised them in May 2026.
   Both repositories now return an access-blocked message, but
   any workflow that referenced them in the intervening days ran
   attacker code with the permissions of the calling repository.
   Teams should grep their workflow files for either action,
   rotate every secret those workflows touched, and pin
   third-party actions to reviewed commit hashes.
   - The Hacker News: https://thehackernews.com/2026/09/compromised-github-actions-came-back.html
