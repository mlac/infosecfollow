3. DEFAULT KEYS AND SPOOFED WORKLOADS IN AI PLUMBING
   AI Security · [ai, identity, cloud]
   Latest developments: Wiz Research reported that nearly one in
   ten internet-facing LiteLLM gateways it scanned in February
   2026 accepted sk-1234, the example administrator key printed
   in LiteLLM's own setup guide; Palo Alto Networks' Unit 42
   showed how root access on a single Kubernetes node lets an
   attacker read SPIFFE and SPIRE metadata and impersonate every
   workload identity sharing that node; and Dark Reading
   detailed workflow identity hijacking, which reaches
   enterprise data through an unauthenticated entry point and
   walks past standard controls.
   An AI gateway sits between a company's applications and the
   model providers it pays, and its administrator key opens
   every request, budget, and provider credential behind it.
   Rotate the default keys, pull gateways off the public
   internet, and treat a compromised node as a compromise of
   every workload identity on it.
