2. CHROME V8 ZERO-DAY UNDER ATTACK
   Vulnerabilities and Exploits · [zero-day, patch, browser]
   Latest developments: Google shipped a Chrome update on
   September 3, 2026, fixing 12 flaws, among them
   CVE-2026-85046, a type-confusion bug in the V8 JavaScript and
   WebAssembly engine rated 8.8 that attackers already exploit
   in the wild, the sixth Chrome zero-day Google has patched in
   2026.
   Every Chrome build before 152.0.7977.82 carries the flaw,
   which a remote attacker triggers through a crafted web page.
   Google fixed it in Chrome 152.0.7977.82 and .83 for Windows
   and macOS and 152.0.7977.82 for Linux; administrators should
   force the update across managed fleets and restart browsers
   to apply it.
   - The Hacker News: https://thehackernews.com/2026/09/google-releases-chrome-update-to-patch.html
   - BleepingComputer: https://www.bleepingcomputer.com/news/security/google-warns-of-new-chrome-zero-day-flaw-exploited-in-attacks/

5. POSTGRESHELL FLAW HANDS ATTACKERS POSTGRESQL SUPERUSER
   Vulnerabilities and Exploits · [vulnerability, patch,
   database]
   Latest developments: Researchers disclosed PostGREShell,
   tracked as CVE-2026-6471, a 12-year-old PostgreSQL
   vulnerability that converts low-level replication access into
   code execution on the database server, permanent superuser
   privileges, and a persistent backdoor.
   The bug rewards any attacker who obtains a replication
   credential, a role many deployments hand out freely for
   standby servers and backup tooling. Database administrators
   should apply the PostgreSQL updates, audit every account
   carrying the replication attribute, and hunt for unexpected
   superuser grants.
   - SecurityWeek: https://www.securityweek.com/12-year-old-postgresql-vulnerability-enables-database-server-takeover/

6. TOY GHOULS HIDES COMMAND SERVERS IN HIVEMQ AND ELEMENT
   Ransomware and Cybercrime · [backdoor, apt, c2]
   Latest developments: Kaspersky's Global Emergency Response
   Team documented two new backdoors from the group it tracks as
   Toy Ghouls, one taking commands through a HiveMQ MQTT broker
   and the other through the Matrix-based Element messenger.
   Both variants route operator traffic over legitimate

   from workstations and servers as anomalies worth
   investigating.

8. RESEARCHERS CATALOG 39 ATTACKS ON PASSKEYS
   Vulnerabilities and Exploits · [authentication, research]
   Latest developments: The authentication vendor Token
   published 39 methods for compromising passkey-based logins,
   every one of them working around the FIDO2 cryptography
   rather than against it, by abusing authentication prompts,
   synced credentials, enrollment, and account recovery.
   Passkeys kill password phishing and credential stuffing, and
   they leave the trust boundaries on either side of the
   cryptographic handshake intact for attackers to work.
   Identity teams should harden passkey enrollment and recovery
   paths, which remain the weakest link in most rollouts.
   - BleepingComputer: https://www.bleepingcomputer.com/news/security/39-new-methods-that-compromise-passkey-authentication/

9. AI CODING AGENTS FETCH UNREGISTERED PACKAGES
   AI Security · [supply-chain, ai, developer-tools]
   Latest developments: Researchers at a stealth Israeli startup
   scanned 6,214 live domains belonging to defense contractors,
   Fortune 500 companies, and Big Tech firms, pulled 8,265
   llms.txt and llms-full.txt files, and found 120 of them, each
   on a separate site, naming code packages or domains that
   nobody has registered.
   The llms.txt convention tells AI coding agents where to find
   a vendor's libraries and documentation, and an agent that
   follows a dangling pointer installs whatever the first person
   to claim that package name publishes. Security teams should
   inventory their own llms.txt files and register or remove
   every name they reference.
   - Schneier on Security: https://www.schneier.com/blog/archives/2026/09/ai-coding-agents-are-installing-unknown-untrusted-code-on-corporate-networks.html
