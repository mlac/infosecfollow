1. Attacker Agents Hunt AI Provider Keys

AI Security · [ai, credentials]

Latest developments: Amazon's threat intelligence team ran decoy servers that captured the attack agents' own records, which show the agents probing internet-exposed LiteLLM, One API, and Dify installations for stored AI provider keys and then using the stolen keys to run the models that powered the search for more keys; Google warned on November 16, 2026 that threat actors already chain agentic workflows through offensive AI frameworks to automate vulnerability discovery and exploitation at machine speed, with fully automated attacks close behind; the SANS Internet Storm Center began catching requests to /mcp-rest/test/tools/list at its honeypots over the weekend that chain CVE-2026-42271 and CVE-2026-48710 in LiteLLM and Starlette into unauthenticated remote code execution, the path Horizon3.ai documented; and Anthropic shipped Claude Fable 5.2 to regular users and Claude Mythos 5.2 to selected partners, with Fable 5.2 refusing fewer security tasks than earlier versions and Mythos 5.2 finding bugs better.

read more

LiteLLM, One API, and Dify are self-hosted gateways that hold the API keys an organization uses to reach commercial AI models, which makes each exposed console a wallet. Anyone running one on the public internet should rotate every key, require authentication on the management interface, cap spending per key, and install the fixes for CVE-2026-42271 and CVE-2026-48710.

3. NoisyTCP Crashes Linux Servers

Vulnerabilities and Exploits · [patch, dos, linux]

Latest developments: Researchers published NoisyTCP, an 11-year-old Linux kernel flaw that reaches almost every distribution and lets an attacker crash hosts running Nginx, Apache, and SSH servers in their default configurations; SecurityWeek confirmed that attackers now exploit CVE-2026-114713 in UnrealIRCd to execute commands with server and IRC operator privileges; the Tor Project shipped 0.4.9.17 to close several issues, among them a gap in how its built-in denial-of-service defenses handle IPv6, while relay attacks continue; and Rspamd 4.3.0 fixed bugs that let an unauthenticated attacker crash the spam filter's workers with one HTTP request, a header line carrying no colon, or an empty Deliver-To header, and let forged authentication results pass.

read more

All four fixes land on infrastructure organizations run and forget: the kernel, the web server, the IRC daemon, and the mail filter. Patch the kernel and Rspamd, move UnrealIRCd to the fixed build, and update Tor relays.

read more

The SANSAR toolkit defeats the GPU-utilization check many Linux operators rely on, which means billing anomalies and Tor-bound traffic make better detections.

8. Project Zero Drops Its Patch Grace Period

Latest developments: Google's Project Zero will publish the vulnerabilities it finds 90 days after it reports them to a vendor whether or not a fix exists, ending the 90-plus-30 rule the team has followed since 2021, and the deadline falls to 60 days on February 2, 2027 and to 30 days on January 3, 2028 under a policy the team calls Full X; Forescout researchers, running generally available AI models on a limited budget against both source code and compiled binaries, confirmed 99 vulnerabilities across 10 TCP/IP stacks, 66 of them previously unknown, and found many in discontinued devices whose vendors will never issue a patch.

read more

Vendors now get a hard 90 days before Project Zero publishes technical detail, shrinking to 30 days by January 2028. Security teams should expect public bug detail on products nobody maintains and build compensating controls, network segmentation among them, around end-of-life equipment.
